# Solaris Times

Личная еженедельная газета Дениса (воскресенье, 21:00 МСК; № 1–13 выходили ежедневно). Статический сайт на GitHub Pages; правила — в [EDITORIAL.md](EDITORIAL.md).

## Устройство
- `content/YYYY-MM-DD.json` — исходник выпуска (метаданные + HTML тела). Единственное, что редактируется руками.
- `build.py` — собирает `issues/<date>/index.html`, `index.html` (свежий номер), `archive/index.html`, `issues.json`, навигацию ←/→. Шапка: «Свежий номер» · «Архив» · «Печатная версия» (последняя — только на страницах номера и главной, ведёт на PDF этого номера; в архиве скрыта).
- Эмбарго: выпуск с `publish_at` в будущем **не собирается** и не попадает на сайт. Workflow `.github/workflows/pages.yml` пересобирает сайт при push и по расписанию в воскресенье 21:01 МСК (cron `1 18 * * 0`), так что заранее закоммиченный номер появляется ровно к выходу. Сгенерированный HTML в репозитории можно не коммитить — Actions собирает его сам.

## Печатная версия
`build.py` для каждого опубликованного номера делает `issues/<date>/print.html` и A4‑PDF `issues/<date>/solaris-times-<date>.pdf` (Playwright/Chromium, print CSS — `assets/print.css`, без источников: ссылки становятся обычным текстом, строки «Источник…» (`.src`) скрыты; подписи и лицензии фото сохраняются). PDF генерируется **в GitHub Actions** при каждой сборке (шаг ставит playwright+chromium), поэтому коммитить его не нужно; `*.pdf` в `.gitignore`. Номер с будущим `publish_at` не собирается вовсе — ни HTML, ни PDF. Локально: `pip install playwright && python3 -m playwright install chromium`; `--no-pdf` пропускает PDF.

## Процедура еженедельного выпуска (воскресенье)
1. `git pull`. `date` = воскресенье, `week` = [понедельник, воскресенье]. Проверить, что `content/<дата>.json` ещё нет. Если есть — не дублировать, только править.
2. Прочитать `EDITORIAL.md` и `items` последних выпусков в `issues.json`, чтобы избежать повторов.
3. Собрать материалы за неделю (пн–вс) для всех частей и рубрик из `EDITORIAL.md`, проверить первоисточники и даты событий, скачать картинки с лицензией в `assets/img/`.
4. Создать `content/<дата>.json` по `TEMPLATE/issue.example.json` (структура — в `TEMPLATE/README.md`): `"kind": "weekly"`, `number` = предыдущий + 1, `publish_at` = `<дата>T21:00:00+03:00`.
5. Объём ≈4500–6000 слов (35–45 минут; `build.py` предупредит, если сильно вне диапазона). Локально: `python3 build.py --now <дата>T21:00:00+03:00`, открыть `issues/<дата>/index.html` (десктоп и 390px) и PDF (≈12 полос, `pdfinfo`).
6. Перед коммитом убрать локальную сборку (`git checkout -- index.html archive issues.json issues; git clean -fd issues`), commit + push до 21:00.
7. После 21:01 МСК (если cron опаздывает — пустой коммит после 21:00 запускает деплой): открыть живые `/`, `/issues/<дата>/`, `/archive/`, `/issues.json`, PDF; проверить картинки и навигацию.
