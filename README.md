# Solaris Times

Личная утренняя газета Дениса. Статический сайт на GitHub Pages; правила — в [EDITORIAL.md](EDITORIAL.md).

## Устройство
- `content/YYYY-MM-DD.json` — исходник выпуска (метаданные + HTML тела). Единственное, что редактируется руками.
- `build.py` — собирает `issues/<date>/index.html`, `index.html` (свежий номер), `archive/index.html`, `issues.json`, навигацию ←/→.
- Эмбарго: выпуск с `publish_at` в будущем **не собирается** и не попадает на сайт. Workflow `.github/workflows/pages.yml` пересобирает сайт при push и по расписанию в 09:01 МСК, так что заранее закоммиченный номер появляется ровно к выходу. Сгенерированный HTML в репозитории можно не коммитить — Actions собирает его сам.

## Процедура ежедневного выпуска
1. `git pull`. Проверить, что `content/<дата>.json` ещё нет (`ls content/`; и `issues.json` на сайте). Если есть — не дублировать, только править.
2. Прочитать `EDITORIAL.md` и `items` последних выпусков в `issues.json`, чтобы избежать повторов.
3. Собрать материалы (веб-поиск, проверка первоисточников, даты событий), скачать картинки с лицензией в `assets/img/`.
4. Создать `content/<дата>.json` по `TEMPLATE/issue.example.json`: `number` = предыдущий + 1, `publish_at` = `<дата>T09:00:00+03:00`.
5. Локально проверить: `python3 build.py --now <дата>T09:00:00+03:00`, открыть `issues/<дата>/index.html` (десктоп и 390px).
6. Перед коммитом вернуть обычную сборку `python3 build.py` (будущий номер не попадёт в выдачу), commit + push до 09:00.
7. После 09:01 МСК: открыть живые `/`, `/issues/<дата>/`, `/archive/`, `/issues.json` и перечитать опубликованный номер; проверить картинки и навигацию.
